# MADINLASHES

Сайт наращивания и ламинирования ресниц в Бишкеке, ориентировочный адрес: Исанова, 172. React / Vite, сервер Express, PostgreSQL и Redis.

## Демо

[Сайт](https://interfaces2005-glitch.github.io/test/) · [Демоадминка](https://interfaces2005-glitch.github.io/test/#admin)

GitHub Pages использует VITE_DEMO=true. Записи, чеки, фото и настройки сохраняются в IndexedDB этого браузера и синхронизируются между его вкладками. Данные разных посетителей не объединяются. Очистка данных сайта удаляет демоданные. В демо нельзя переводить реальные деньги, WhatsApp не отправляется.

Вход в демоадминку: логин `admin`, пароль `MadinDemo2026!`. Это публичные демонстрационные данные, а не защита персональных данных на статическом хостинге. Форма проверяет оба поля, сессия хранится в sessionStorage вкладки на 12 часов, пароль в хранилище не сохраняется. Есть выход из кабинета. Настоящие проверки доступа к API выполняет сервер.

## Запись и предоплата

- Услуги → мастер → дата/время → контакты. Мобильная нижняя панель открывает разделы в окнах.
- По умолчанию 09:00–20:00, перерыв 14:00–14:30, начало каждые 30 минут, минимум 30 минут до визита, горизонт 90 дней. Смены и выходные редактируются в админке.
- На контакты даётся резерв 6 минут. Новый клиент вносит 500 сом по QR; сумма входит в стоимость услуги. На перевод и загрузку чека по умолчанию 30 минут.
- Загруженный чек переводит заявку на проверку и удерживает время. В разделе **Предоплаты** мастер проверяет поступление в банке, отмечает проверку и подтверждает сумму либо возвращает заявку на уточнение. Автоматической сверки с банком нет.
- После подтверждения оплаты номер попадает в базу. Клиенты базы записываются без предоплаты. Существующих клиентов можно добавить вручную в разделе **Клиенты**. Неоплаченная или отменённая новая заявка льготу не создаёт. Прежние подтверждённые/завершённые визиты переносятся миграцией.
- Клиент определяется по нормализованному номеру +996. Проверки владения номером пока нет.
- Приватная ссылка позволяет клиенту видеть статус, загрузить чек и отменить визит. Её следует передавать только владельцу записи. Возврат денег согласуется со студией; автоматических возвратов нет. Перенос оформляется отменой и новой записью.

В серверной версии заявки с предоплатой доступны после настройки QR. В демо процесс можно показать без настоящего QR.

## Админка

Доступны журнал, расписания, услуги/цены, мастера, клиенты, предоплаты, уведомления и редактор сайта.

**Редактор сайта**: тексты, главное фото, контакты, цвета, шрифты, FAQ, правила и фото работ (добавление, замена, подписи, порядок, скрытие, удаление). Галерея изначально пуста. Предпросмотр показывает черновик, сохранение проверяет конфликты версий между вкладками. Услуги архивируются, мастера скрываются без удаления истории. Маникюра в новых записях нет.

**Редактор сайта → Запись и оплата**: загрузите QR банка/кошелька, укажите получателя и инструкцию. По умолчанию сумма 500 сом, время оплаты 30 минут, напоминание 60 минут. QR сохраняется в PNG без потерь, фотографии оптимизируются в WebP. Надпись часов в контактах не меняет графики мастеров.

В **Мастера** укажите приватный номер WhatsApp +996 и согласие на уведомления. Сервер не возвращает эти поля публичным каталогом. Чеки JPG/PNG/WebP/PDF до 6 МБ хранятся отдельно от галереи; на сервере получить файл чека может только администратор. Фото, чеки и настройки входят в резервную копию PostgreSQL. Удаление фото из галереи убирает ссылку, сам файл сохраняется до отдельной очистки.

## WhatsApp клиенту и мастеру

Клиент отдельно выбирает согласие на WhatsApp. При новой заявке ему готовится сообщение о предоплате, после проверки — подтверждение и напоминание за час. Для клиента базы подтверждение готовится сразу. Мастер получает уведомления о новой записи, чеке, подтверждении оплаты и отмене. Напоминание создаётся для будущего подтверждённого визита; отменённые и устаревшие задания пропускаются.

**Уведомления** показывают получателя, текст, время и состояние. «Передано» означает принятие запроса провайдером, а не доставку на телефон. Обработчика статусов доставки пока нет.

Для настоящей отправки нужен постоянно работающий сервер и один вариант в .env:

1. WHATSAPP_WEBHOOK_URL (HTTPS) и WHATSAPP_WEBHOOK_TOKEN — адаптер WhatsApp Business провайдера. Получает JSON {id,to,kind,audience,template,language,text,parameters,manageUrl} и заголовок Idempotency-Key. Адаптер должен устранять повторы и применять одобренные шаблоны.
2. Meta Cloud API: WHATSAPP_ACCESS_TOKEN, WHATSAPP_PHONE_NUMBER_ID, поддерживаемая вашим аккаунтом WHATSAPP_API_VERSION, WHATSAPP_LANGUAGE и имена одобренных шаблонов WA_*_TEMPLATE из .env.example.

Каждый шаблон использует **9 текстовых параметров body**: студия, имя клиента, услуги, дата, время, мастер, адрес, сумма/условие предоплаты, приватная ссылка (мастеру — админка). Одобренный шаблон должен соответствовать событию и этому порядку. Получатели — цифры с кодом страны без плюса.

Формат запроса: [официальная коллекция Meta — Send Message Template Text](https://www.postman.com/meta/whatsapp-business-platform/request/o65u5m5/send-message-template-text).

Очередь PostgreSQL обрабатывается каждые 15 секунд, ошибки повторяются с задержкой до 8 раз. Без провайдера/шаблона отправок нет. Перед подключением проверьте очередь: актуальные старые задания могут уйти после настройки. При таймауте прямого Cloud API возможны дубликаты; webhook должен дедуплицировать ID. Секреты не сохраняйте в Git.

## Запуск

Нужен Node.js 22+. В PowerShell используйте npm.cmd, если npm.ps1 блокируется.

```powershell
npm.cmd ci
npm.cmd run dev
```

Для отдельного порта: npm.cmd run dev -- --port 5174 --strictPort.

Серверу нужны PostgreSQL 17+ с btree_gist и Redis 7+:

```powershell
docker compose up -d
Copy-Item .env.example .env
# Отредактируйте .env перед следующими командами.
npm.cmd run db:migrate
npm.cmd run build
npm.cmd start
```

Задайте подключения, VITE_DEMO=false, APP_ORIGIN, ADMIN_LOGIN (по умолчанию admin), случайный ADMIN_PASSWORD минимум 16 символов и стабильный случайный BOOKING_LINK_SECRET. Сервер проверяет логин и пароль; они не передаются в сборку браузера. Логин не зависит от регистра и пробелов по краям, пароль проверяется точно. Открывайте точный APP_ORIGIN (по умолчанию http://localhost:3001). Повторяйте миграцию при обновлении: она сохраняет историю, добавляет платежи/клиентов/чеки/очередь и один раз переносит стандартное начало с 10:00 на 09:00.

Для разработки Vite задайте APP_ORIGIN=http://localhost:5173; /api проксируется на 3001. В production: NODE_ENV=production, HTTPS и reverse proxy на 127.0.0.1:3001. Отключите буферизацию /api/events. Сервер доверяет proxy только с loopback. Базы не выставляйте в интернет, замените примерные пароли Docker и настройте резервные копии.

Авторизация одного администратора: HttpOnly/SameSite cookie на 12 часов, проверка Origin и лимит попыток. Redis атомарно резервирует сегменты, PostgreSQL исключает пересекающиеся интервалы, SSE передаёт сигнал изменения без персональных данных. Часовой пояс Asia/Bishkek. Сервер и очередь должны работать постоянно.

## Проверки

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e
node tests/pages-check.mjs
```

Браузерные тесты используют свободный порт 5175 и Chrome из C:/Program Files/Google/Chrome/Application/chrome.exe. Проверяются запись, гонки, CMS, мобильные размеры, предоплата, чек, подтверждение, повторная запись без предоплаты и приватная ссылка. Скриншоты — test-results. Pages-проверка проверяет сборку в подпапке.

PostgreSQL-тест запускается только при TEST_DATABASE_URL во временной схеме (нужны CREATE SCHEMA и btree_gist). Без базы явно пропускается. Тесты демо не подтверждают работу развёрнутых PostgreSQL/Redis, банка и WhatsApp; инфраструктуру и доставку нужно проверить после подключения.
