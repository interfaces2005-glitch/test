# MADINLASHES — студия красоты

Студия наращивания и ламинирования ресниц. Маникюр убран из новых записей; прежняя история визитов сохраняется.

## Редактор сайта в админке

Откройте `/#admin` → **Редактор сайта**. Доступны:

- **Тексты:** название, подпись логотипа, заголовки, описания, надписи первого экрана, кнопка записи и главное фото.
- **Фото работ:** до 24 фотографий, загрузка JPG/PNG/WebP до 6 МБ, замена, подпись, категория, порядок, скрытие и удаление из галереи. Галерея изначально пуста: фотографии чужих работ не подставляются.
- **Контакты:** город, адрес и примечание, номер +996, часы работы, Instagram и Telegram. Карта берёт адрес из этих полей. Надпись о часах не меняет графики записи.
- **Оформление:** цвета, стиль шрифта заголовков, видимость мастеров, галереи и FAQ.
- **Вопросы и ответы:** добавление, редактирование и удаление FAQ.
- **Правила:** реквизиты оператора, текст политики конфиденциальности и правила отмены.

Сначала изменения остаются в черновике. **Предпросмотр** показывает тот же интерфейс сайта, не создавая записей. **Сохранить сайт** применяет настройки; другие открытые вкладки обновляются. При уходе из редактора с несохранёнными изменениями появляется предупреждение. «Загрузить сохранённую версию» отменяет текущий черновик с подтверждением. Если сайт уже сохранён из другого окна, конфликт версий не позволит незаметно перезаписать его.

В **Услуги и цены** можно добавлять, редактировать и удалять услуги, назначать мастеров и менять фото. Категории: наращивание и ламинирование. Удаление архивирует услугу для новых записей; существующие визиты остаются. В **Мастера** редактируются имя, специализация и фото; мастер может быть скрыт от новых записей без отмены существующих визитов.

**В опубликованном статическом демо редактор меняет только данные вашего браузера, не общий сайт для всех посетителей.** Фотографии лежат в IndexedDB; очистка данных сайта удалит демоданные. В серверной версии настройки, версии и файлы хранятся в PostgreSQL и видны всем посетителям. Для обновления существующей серверной базы повторно выполните `npm.cmd run db:migrate`: миграция добавляет таблицы `site_content` и `media`, поддерживает архивирование услуг и сохраняет историю. Загруженные файлы оптимизируются в WebP, проверяются по MIME и сигнатуре; серверный upload доступен только администратору. Удаление фото из галереи убирает ссылку с сайта; неиспользуемые файлы сохраняются в хранилище до отдельной очистки, чтобы не ломать другие ссылки и черновики.

Снимки и содержимое сайта входят в резервную копию PostgreSQL. Тест реальной базы в текущем окружении пропускается без `TEST_DATABASE_URL`; модульные и браузерные проверки не являются доказательством работы развёрнутой инфраструктуры.

Адаптивный сайт на React + Tailwind CSS и отдельный сервер Node.js / Express, PostgreSQL, Redis, SSE.

## Что работает

- Главная страница, фильтр услуг, мастера, фотогалерея с увеличением, FAQ, карта.
- Четыре шага записи: несколько услуг → совместимый мастер → календарь → контакты. Стоимость и длительность складываются. Услуги выполняются последовательно одним мастером.
- График 10:00–20:00 по умолчанию, обед 14:00–14:30, шаг начала 30 минут, минимум 30 минут до визита, горизонт 90 дней. Индивидуальные смены, выходные и несколько перерывов настраиваются в кабинете.
- Резерв на 6 минут, проверка актуальности перед записью, отмена и экспорт Google / Apple Calendar.
- Кабинет `/#admin`: день/неделя по мастерам, ручная запись, пять статусов, графики, каталог с привязкой к мастерам, поиск гостей и история. Сумма чеков учитывает только завершённые визиты.
- Сервер: Redis Lua резервирует все 15-минутные сегменты интервала атомарно. PostgreSQL advisory lock сериализует операции мастера на дату; GiST exclusion constraint запрещает пересечение интервалов даже при пустом календаре. Это защищает и от «фантомных» вставок, которые обычный `SELECT ... FOR UPDATE` пустого результата не блокирует.
- SSE через PostgreSQL LISTEN/NOTIFY передаёт только сигнал изменения без персональных данных; heartbeat и обновление раз в 30 секунд. Работает между экземплярами сервера.
- Telegram-уведомления администратору, SMS/WhatsApp через настраиваемый webhook, очередь PostgreSQL, повторы с задержкой, напоминания за 24 и 2 часа. Без ключей ничего не отправляется.

## Демо и серверная версия

**Опубликованный Sites — приватная статическая демонстрация.** `VITE_DEMO` по умолчанию включён. Данные и фотографии сохраняются в IndexedDB одного браузера. Транзакции IndexedDB защищают от одновременных изменений, BroadcastChannel обновляет другие вкладки. localStorage используется только как зеркало для совместимости и переноса старых демоданных. Между устройствами демоданные не синхронизируются. Кабинет демоверсии открыт, поскольку настоящих клиентов в нём нет. В демо вводите вымышленные данные.

**Настоящая запись требует запуска сервера** с PostgreSQL и Redis и сборки `VITE_DEMO=false`. Сервер не переключается на демоданные при недоступности API. Статический Sites не запускает Express/PostgreSQL/Redis: серверную версию следует размещать на VPS/Node-хостинге с HTTPS и тем же origin для UI и `/api`.

## Локальный запуск демо

Требуется Node.js 22 или новее. В PowerShell используйте `npm.cmd`, если политика исполнения блокирует `npm.ps1`.

```powershell
npm.cmd ci
npm.cmd run dev
```

## Запуск серверной версии

1. Установите Docker Desktop или предоставьте собственные PostgreSQL 17+ и Redis 7+.
2. Скопируйте `.env.example` в `.env`. Укажите случайный `ADMIN_PASSWORD` минимум 16 символов, корректные подключения и `APP_ORIGIN`. Не сохраняйте `.env` в Git.
3. По умолчанию `APP_ORIGIN=http://localhost:3001`: открывайте именно этот адрес (не `127.0.0.1`), чтобы проверка Origin совпала.

```powershell
docker compose up -d
Copy-Item .env.example .env
# Отредактируйте .env перед следующими командами.
npm.cmd run db:migrate
npm.cmd run build
npm.cmd start
```

Vite читает `VITE_DEMO=false` из `.env` при сборке. Для разработки реального UI откройте Vite и задайте `APP_ORIGIN=http://localhost:5173`; прокси направляет `/api` на порт 3001. При возврате к демо укажите `VITE_DEMO=true` и пересоберите.

В production задайте `NODE_ENV=production`, `APP_ORIGIN=https://ваш-домен`, включите HTTPS reverse proxy к `127.0.0.1:3001`. SSE требует отключения буферизации `/api/events`; сервер передаёт `X-Accel-Buffering: no`. Приложение доверяет proxy только с loopback. Базы не выставляйте в интернет. Примерные пароли Docker предназначены для локального запуска.

Вход в кабинет использует HttpOnly/SameSite cookie на 12 часов, проверку Origin для изменений и лимит попыток. Это один администратор; роли персонала и саморегистрация не реализованы. Сервер и обработчик уведомлений должны работать постоянно; при остановленном процессе напоминания не отправляются. Доставка Telegram с повторами может дублироваться при сетевом таймауте. SMS webhook получает `Idempotency-Key`; провайдер должен поддерживать дедупликацию.

## Интеграции

- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`: уведомления о создании и отмене.
- `SMS_WEBHOOK_URL`: HTTPS POST с `{id, phone, text}`, заголовками `Authorization: Bearer …` и `Idempotency-Key`. Подключите адаптер своего SMS/WhatsApp-провайдера; его URL, формат авторизации и доступ ещё не предоставлены.
- `STUDIO_TIMEZONE`: IANA зона (по умолчанию Asia/Bishkek); сервер рассчитывает время независимо от системного часового пояса.
- Ненастроенные каналы остаются в очереди. После настройки старые уведомления могут быть отправлены; перед боевым подключением проверьте очередь `notifications`.

## Проверки

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e
```

Браузерный тест запускает Vite на 127.0.0.1:5173 и использует установленный Chrome на Windows. При другом расположении Chrome измените `executablePath`. Скриншоты сохраняются в `test-results/`. Дополнительно проверяются одновременные запросы из двух вкладок: выигрывает один резерв, пересекающиеся интервалы закрываются, освобождение возвращает слот.

Тест реальных конкурентных вставок запускается только при `TEST_DATABASE_URL`, использует отдельную временную схему и удаляет только её. Нужны права CREATE SCHEMA и расширение `btree_gist`. Без PostgreSQL он явно пропускается; модульные и браузерные тесты не заменяют интеграционную проверку.

## Что заполнить перед публичным запуском

Название MADINLASHES, город Бишкек и ориентировочный адрес Исанова, 172 предоставлены владельцем. Мастера, цены, фото, отзыв и график — демонстрационные. Замените их реальными данными в разделе «Редактор сайта», «Услуги и цены» и «Мастера» кабинета. Начальные значения лежат в `shared/catalog.mjs` и `shared/site-content.mjs`. Нужно подтвердить расположение и добавить контактный номер +996, соцсети, реквизиты и утверждённые правила/политика. Контактный телефон и соцсети намеренно не выдуманы. Перед публичным запуском дополните политику оператором данных, сроками хранения и способом обращения; установите регулярные резервные копии PostgreSQL.

Сейчас отмена доступна на экране успеха и у администратора. Отдельного клиентского кабинета и внешней ссылки на отмену нет. Перенос оформляется администратором как отмена и новая запись; отдельного атомарного переноса пока нет.

## Навигация

Кнопки записи открывают окно с четырьмя шагами. Меню открывает разделы в окне с вкладками; страница под ним остаётся на месте. Закрытие по крестику или Escape возвращает к предыдущему месту. Незавершённый резерв освобождается при закрытии окна. Формат номера: +996 (XXX) XXX-XXX, время студии — Asia/Bishkek, суммы — в сомах.
