# Показ MADINLASHES заказчику через GitHub Pages

Эта копия подготовлена для отдельного GitHub-репозитория. Она содержит актуальный интерфейс MADINLASHES, запись и редактор сайта в деморежиме. Файлы доступа к Sites, история исходного репозитория, реальные `.env` и данные браузера сюда не копируются.

## Публикация

1. Создайте репозиторий, например `madinlashes-demo`. На GitHub Free для Pages нужен публичный репозиторий; для приватного — подходящий платный план. Публичный репозиторий открывает исходный код всем, а ссылку на демо можно передать заказчику.
2. Загрузите эту папку в ветку `main`, включая скрытую папку `.github` и `package-lock.json`. Не загружайте `node_modules`, `dist`, реальные `.env` и файлы с доступами.
3. В репозитории выберите **Settings → Pages → Source → GitHub Actions**.
4. В **Actions** запустите **Publish MADINLASHES demo → Run workflow** либо отправьте изменение в `main`.
5. После успешного запуска ссылка будет в **Settings → Pages** и в результате workflow. Обычно это `https://<пользователь>.github.io/<репозиторий>/`. Админка открывается с `#admin` в конце ссылки.

Workflow устанавливает зависимости, запускает модульные проверки, собирает сайт и публикует только `dist`. Сборка принудительно использует `VITE_DEMO=true`. Пути картинок и файлов поддерживают публикацию в подпапке репозитория.

## Что увидит заказчик

- Сайт студии наращивания и ламинирования ресниц в Бишкеке.
- Выбор услуги, мастера, времени и демонстрационная запись.
- Открытая демоадминка: тексты, фото, услуги, мастера, оформление и предпросмотр.

Настройки, записи и фото из админки сохраняются отдельно в браузере каждого посетителя и для каждого адреса сайта. Правки, сделанные вами на localhost или Sites, автоматически в GitHub Pages не попадут. Данные не синхронизируются с заказчиком, сообщения не отправляются. Для общего рабочего сайта нужен сервер; PostgreSQL, Redis и Express не запускаются на GitHub Pages.
